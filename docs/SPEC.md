## 1. 목적과 문서 상태

**Arete Club의 정체성·연구 관심 분야·프로젝트를 소개하는 정적 단일 페이지에, 밝은 수평선에서 깊은 남색으로 이어지는 3D 히어로를 구현한다.**

방문자는 첫 화면에서 독립 AI 연구·개발 조직이라는 정체성을 이해하고, 본문에서 철학과 연구 관심 분야를 읽은 뒤 실제 프로젝트를 확인할 수 있어야 한다.

- 이 문서는 합의된 기획과 기술 스택을 정리한 **구현 전 검토용 스펙**이다. 구현 착수 승인을 의미하지 않는다.
- 사용자와 합의한 항목은 위 `decisions_carried_in`에 기록한다. 아래의 세부 동작·검증 도구는 그 합의를 구현하기 위한 **스펙 제안**이며 문서 검토 대상이다.
- 브랜드·콘텐츠의 원문은 [브랜드 정체성 PRD](arete-club-brand-identity-prd.md)다. 이번 대화에서 변경한 색상 흐름·히어로 3D 범위·스택은 본 문서를 따른다.
- 작성 시점에는 위 브랜드 문서와 기존 `SPEC.md`만 확인되었으며, 구현 코드·패키지 설정·Git 저장소·로드맵은 없다. 아래 컴포넌트·데이터 타입·명령은 **향후 구현 계약**이다.

## 2. 범위

### 포함

- 단일 경로 `/`의 정적 랜딩 페이지.
- Hero → About / Philosophy → What We Explore → Projects → Contact / Footer 순서.
- 히어로의 추상적 3D 수평선, 레이어의 깊이감, 스크롤과 연결된 색상·시점 변화.
- 남색 본문, 밝은 글자, 넉넉한 여백, 반응형 배치.
- 섹션 앵커 내비게이션과 프로젝트 데이터 배열.
- 공식 URL·이메일 확인 후 노출하는 외부 링크.
- 기본 접근성, 페이지 제목·설명·Open Graph 메타데이터.

### 초기 범위 제외

- 본문 전체를 3D 공간으로 구성하는 연출, 스크롤 강제 이동·스냅, 별도의 스무스 스크롤 라이브러리.
- 사실적인 바다 시뮬레이션, 선박·해적 테마, 영상 배경, 입자 쇼, 무거운 3D 모델·후처리 효과.

### 5.2 레이아웃·텍스트 — 구현 제안

- 넓은 여백과 명확한 제목·본문 계층을 사용한다. 본문은 기본 16px 이상, 행간 1.6 이상을 출발값으로 삼는다.
- 본문 단락은 최대 폭을 제한하고, 모바일에서는 단일 열로 읽는다. 프로젝트 카드는 화면 폭에 따라 열 수를 조정한다.
- 히어로의 글자·CTA는 HTML로 렌더링한다. 캔버스 안에 텍스트나 링크를 그리지 않는다.
- 텍스트에는 스크롤 연동 회전·기울임·확대를 적용하지 않는다. 일반적인 페이지 이동과 짧은 전환만 허용한다.
- 일반 텍스트는 대비 4.5:1 이상, 큰 텍스트는 3:1 이상을 검증 기준으로 삼는다. 보조 글자와 링크도 확인한다.
- 밝은 시작에는 짙은 글자, 남색 구간에는 밝은 글자를 사용한다. 중간 전환에도 글자와 배경이 비슷한 밝기로 겹치지 않도록 글자색 변경 시점과 텍스트 뒤 배경을 조정한다.
- 서체는 한글·영문을 지원하는 산세리프 계열로 선정한다. 서체명과 최종 간격은 시안 검토에서 결정한다.

## 6. 히어로와 스크롤 동작

### 6.1 장면의 흐름

| 상태 | 배경·공간 | 스크롤에 따른 변화 |
| --- | --- | --- |
| 시작 | 밝은 공간과 옅은 수평선 | 첫 로드에서 브랜드명·슬로건·소개·CTA를 읽을 수 있음 |
| 중간 | 하늘색과 겹쳐진 곡면·레이어 | 제한된 카메라 이동과 레이어 간 시차로 깊이 표현 |
| 끝 | 수평선이 시야 위쪽으로 멀어지는 깊은 남색 | 장면의 끝 배경이 본문 배경과 이어짐 |
| 본문 | 남색과 밝은 글자 | 일반적인 세로 스크롤로 콘텐츠를 읽음 |

색상과 공간의 변화는 **히어로 구간의 스크롤 진행도**를 따른다. 스크롤을 되돌리면 같은 위치에서 같은 장면으로 돌아온다. 시간에 따라 자동으로 흰색에서 남색까지 진행하는 인트로가 아니다.

### 6.2 동작 계약 — 구현 제안

- Three.js 캔버스는 히어로 배경 하나로 한정한다. 곡면·레이어와 카메라로 공간감을 구성한다.
- GSAP ScrollTrigger의 진행도를 장면과 배경색에 연결한다. 스크롤 입력을 가로채지 않는다.
- 히어로의 높이·전환 구간 길이는 모바일·데스크톱 시안에서 조정한다. 본문 읽기에 긴 연출 구간을 강제하지 않는다.
- 히어로를 벗어나거나 탭이 보이지 않을 때 렌더링 루프를 중지한다. 히어로 재진입 시 현재 스크롤 위치로 장면을 동기화한다.
- 화면 크기 변경 시 캔버스·카메라·스크롤 범위를 다시 계산하고, 이전 렌더러·이벤트·타임라인이 중복으로 남지 않도록 정리한다.
- Projects 앵커로 바로 이동하거나 스크롤 위치가 복원되어도 본문이 즉시 읽혀야 한다.

### 6.3 접근성·성능 대체 경로 — 구현 제안

- `prefers-reduced-motion: reduce`에서는 카메라·시차·스크롤 애니메이션을 사용하지 않고, 밝은 시작에서 남색 하단으로 이어지는 정적 CSS 배경을 표시한다.
- WebGL 초기화 실패·컨텍스트 손실·3D 모듈 로딩 실패 시에도 같은 정적 배경과 HTML 콘텐츠를 제공한다.
- JavaScript가 꺼져 있어도 소개·프로젝트·앵커 링크를 사용할 수 있어야 한다. 배경과 글자 대비는 기본 CSS만으로 확보한다.
- 모바일에도 같은 콘텐츠와 색상 방향을 유지하되 캔버스 해상도·레이어 복잡도를 줄인다. 모바일 3D를 기본적으로 제거하는 결정은 하지 않는다.
- 캔버스는 장식 요소로 처리하고 포인터·키보드 탐색을 방해하지 않는다.
- 첫 화면의 텍스트 표시를 3D 준비 완료까지 지연하지 않는다. 3D 의존성은 히어로 모듈에서 지연 로딩하도록 설계한다.

## 7. 기술 스택과 책임 분리

| 역할 | 기술 / 방식 | 책임 |
| --- | --- | --- |
| 페이지 | Astro, 정적 출력 | 빌드 시 섹션 HTML과 메타데이터 생성 |
| 언어 | TypeScript | 데이터·DOM·장면 코드의 타입 검사 |
| 3D | Three.js | 히어로 장면·카메라·렌더러·리소스 정리 |
| 스크롤 | GSAP + ScrollTrigger | 히어로 진행도·배경·카메라 변화 동기화 |
| 스타일 | Astro 컴포넌트 CSS + 공통 CSS 변수 | 레이아웃·반응형·색상·글자·간격 |
| 콘텐츠 | 로컬 타입 데이터 배열 | 프로젝트 카드 추가·수정, 확인된 링크 관리 |
| 검증 제안 | Astro check / ESLint / Vitest / Playwright | 타입·정적 검사, 데이터와 계산, 실제 브라우저 동작 |

Node.js·Astro·각 패키지의 정확한 버전은 구현 착수 시 안정 버전과 호환성을 확인하고 lockfile로 고정한다. 이 문서는 미확인 버전 번호를 지정하지 않는다. 운영 서버·React·React Three Fiber·Tailwind는 이 스택에 포함하지 않는다.

### 7.1 구성 요소의 책임

- **페이지·레이아웃:** 내비게이션, 시맨틱 섹션, 본문, 기본 메타데이터를 정적 생성한다.
- **히어로 HTML·CSS:** 제목·소개·CTA와 3D 실패 시 표시할 기본 배경을 담당한다.
- **히어로 장면 모듈:** 초기화, 크기 변경, 그리기, 중지·재개, 리소스 해제를 담당한다.
- **스크롤 제어 모듈:** 히어로 진행도를 계산하고 장면·색상을 갱신한다. 사용자 스크롤 위치를 강제로 변경하지 않는다.
- **프로젝트 데이터:** 배열 한 곳에서 관리하고 빌드 시 카드로 출력한다. 상세 디렉터리와 파일명은 구현 시 확정한다.

### 7.2 콘텐츠 데이터 계약

아래는 기존 API가 아닌 새 구현을 위한 타입 제안이다.

```typescript
type Project = {
  name: string;
  category: string;
  summary: string;
  status: string | null;
  href: string | null;
};

type OfficialChannels = {
  github: string | null;
  email: string | null;
};
```

- `status`와 `href`는 각각 확인된 값만 채운다. 확인 근거는 `PROGRESS.md`에 기록한다.
- `null`인 상태 배지·링크는 렌더링하지 않는다. “확인 필요” 같은 내부 작업 문구는 웹페이지에 노출하지 않는다.
- 문서에 제시한 두 프로젝트로 시작한다. 존재하지 않는 프로젝트로 개수를 채우지 않는다.

### 7.3 메타데이터

## 9. 테스트 전략

아래는 **향후 구현의 검증 계획**이다. 현재 애플리케이션이나 테스트 명령이 존재하거나 통과했다는 뜻이 아니다. 자동 검사와 브라우저 시각 검토를 함께 수행하며, 이미지 일치만으로 가독성·접근성을 판정하지 않는다.

| ID | 검증 항목 | 방법 / 통과 기준 |
| --- | --- | --- |
| T01 | 정적 콘텐츠 | JS 비활성 브라우저에서 H1·다섯 섹션·네 연구 관심 분야·두 프로젝트 확인 |
| T02 | 카드 데이터·링크 | 데이터 항목과 카드 수 일치, `null` 배지·링크 미노출, 등록된 링크만 출력 |
| T03 | 스크롤 계산 | 진행도 시작·중간·끝과 범위 밖 입력을 단위 테스트, 역방향에서 같은 값 복원 |
| T04 | 히어로 연결 | 브라우저에서 시작·중간·끝 장면과 색상 순서, 역스크롤, 본문 남색 연결 확인 |
| T05 | 가독성·반응형 | 375 / 768 / 1440px 폭에서 가로 넘침·텍스트 잘림·CTA 겹침 없음. 전환 구간 여러 지점의 실제 배경 대비 검사 |
| T06 | 기본 접근성 | 제목 계층·문서 언어·키보드 탭 순서·포커스 표시·앵커 이동·캔버스 장식 처리 확인 |
| T07 | 모션 감소·실패 경로 | 모션 감소 설정, WebGL 실패·컨텍스트 손실·모듈 로딩 실패를 각각 재현하고 정적 배경·콘텐츠·링크 유지 확인 |

검증 도구 제안: Vitest는 데이터 규칙과 스크롤 보간 계산, Playwright는 실제 정적 출력·앵커·스크롤·대체 경로를 담당한다. 기존 v0의 React Testing Library 전제는 제거한다.

프로파일 결과에는 브라우저·기기 또는 에뮬레이션 여부를 기록한다. 데스크톱 모바일 에뮬레이션만 수행했다면 실기기 검증으로 보고하지 않는다. FPS·번들 용량·Lighthouse 점수는 측정 전 성능 보장으로 제시하지 않는다.

## 10. 구현 완료 판정

각 명령은 구현 단계에서 마련할 npm 스크립트 계약이다. 실제 실행 결과와 V01 검토 기록을 `PROGRESS.md`에 남긴다.

- [ ] `npm run check` — Astro·TypeScript 검사 오류 0.
- [ ] `npm run lint` — 린트 오류·경고 0.
- [ ] `npm run test` — T02의 데이터 규칙·T03 단위 테스트 통과.
- [ ] `npm run build` — 정적 빌드 성공, T09 산출물 준비.
- [ ] `npm run test:e2e` — 빌드 산출물 대상 T01·T02·T04–T09 브라우저 검사 통과.
- [ ] `npm run test:visual` — V01 검토용 캡처·기록 생성 성공. 사람이 확인한 항목과 미검증 항목을 별도로 기록.
- [ ] 스펙 항목별 자체 검토 1회 수행 — 콘텐츠·색상 흐름·히어로 범위·스택·I01–I08 대조 결과와 이탈 목록을 기록하고, 미해결 이탈이 없음을 확인.
- [ ] V01 수동 검토에서 읽기 방해·색상 단절·스크롤 정지·콘텐츠 가림의 미해결 항목이 없음을 확인.

테스트·린트·스펙 대조가 끝나기 전 구현 완료로 보고하지 않는다. 문서 작성 완료와 웹페이지 구현 완료를 구분한다.

## 11. 미결 사항과 결정 시점

| 항목 | 결정 시점 | 처리 원칙 |
| --- | --- | --- |
| 본 스펙의 세부 동작·검증 제안 승인 | 구현 착수 전 | 사용자 검토 후 구현 단계로 이동 |
| Git 초기화·작업 브랜치 | 구현 착수 전 | 현재 Git 저장소가 없음. 초기화 후 작업 브랜치에서 진행할 방식 합의 |
| Node.js·패키지 버전과 검증 도구 버전 | 구현 환경 구성 시 | 안정 버전·호환성 확인 후 lockfile 고정 |
| 흰색·하늘색·남색의 정확한 HEX | 첫 시안 검토 시 | 순서는 유지하고 대비 검사 후 색상 토큰 확정 |
| 서체·최종 간격·히어로 길이·카메라 이동량 | 첫 시안 검토 시 | 가독성과 모바일 스크롤 검토 후 확정 |
| 로고 파일 | 첫 시안 전 또는 제공 시 | 미제공이면 텍스트 브랜드명 사용, 새 로고 제작은 별도 범위 |
| 프로젝트 상태·공식 저장소 URL | 해당 배지·링크 노출 전 | 사용자 확인 또는 공개 원문으로 검증. 미확인 값은 `null` |
| 조직 GitHub·이메일 | 해당 링크 노출 전 | 확인 전 생략. 문서 작성·로컬 구현을 차단하지 않음 |
| 호스팅·도메인·공유 이미지 | 공개 배포 결정 시 | 구현 스택과 분리하여 합의. 배포·이미지 제작은 이번 문서 작업 범위 밖 |

로드맵은 아직 없다. 위 시점은 이 스펙의 실행 순서이며 존재하지 않는 로드맵 Phase를 참조하지 않는다.
